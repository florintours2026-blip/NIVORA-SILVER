# تحديث NIVORA SILVER — Luxury Visual Layer

## ما تم تحديثه
- إعادة بناء طبقة المتجر العامة بهوية سوداء/شمبانيا/فضية متوافقة مع مراجع NIVORA المرفقة.
- إصلاح صورة الـHero لتعمل من أصل محلي داخل المشروع بدلاً من مسار مرجعي خاطئ.
- إضافة Hero متجاوب، أقسام الفئات، الأكثر مبيعاً، Editorial، مزايا المتجر، آراء العملاء، والنشرة البريدية.
- إعادة تصميم بطاقات المنتجات مع السعر والخصم والتقييم والمفضلة والسلة.
- تحسين Header وNavigation وFooter وواجهة الهاتف.
- إضافة صور محلية للهوية والمنتجات الأساسية لتقليل الاعتماد على الصور الخارجية.
- إبقاء منطق Firebase الحالي منفصلاً عن طبقة التصميم قدر الإمكان.

## تحصين أمني مضمّن
- منع رفع صلاحية العميل إلى admin/manager عبر تحديث وثيقة المستخدم من المتصفح.
- تقييد إنشاء الطلبات إلى حساب صاحب الطلب، مع تحقق أساسي من العملة والحالة وطريقة الدفع وبنية الطلب.
- تشديد Firebase Storage ليقبل صوراً فقط وبحد أقصى 5MB في مسار المنتجات للمشرفين.
- تنظيف النصوص والروابط القادمة من عروض Firestore قبل عرضها في الواجهة العامة.
- تنظيف أسماء ملفات صور المنتجات قبل تخزينها.
- إزالة معالج القائمة المضمّن inline من الـHeader واستخدام event listeners.

## ملاحظة مهمة حول أمان التجارة الإلكترونية
لا يمكن اعتبار أي متجر يعتمد على سعر أرسله المتصفح محمياً بالكامل من التلاعب بالسعر. هذه النسخة تمنع الكتابة غير المصرح بها وتقلل XSS وتلاعب الصلاحيات، لكن **السعر النهائي والدفع الحقيقي يجب أن يحسبا ويُتحقق منهما في Backend/Cloud Function موثوق قبل إطلاق الدفع الإلكتروني**. قواعد Firestore وحدها لا تكفي لإثبات سعر المنتج من قاعدة المنتجات لكل عنصر في الطلب.
