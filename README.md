# NIVORA SILVER — مشروع متجر فاخر جاهز للتطوير من الهاتف

هذا الإصدار يحول النموذج الأولي إلى **بنية متجر فعلية قابلة للربط بقاعدة بيانات** مع الحفاظ على هوية Dark Luxury المرجعية المرفقة.

## ما الذي أصبح موجودًا؟

- متجر عربي RTL ومتجاوب.
- لوحة إدارة واحدة داخل `admin.html` مصممة للهاتف أولًا.
- Dashboard للمبيعات، الطلبات، المخزون، الربح والتنبيهات.
- إدارة المنتجات والمخزون.
- استيراد منتج من رابط في الواجهة الإدارية.
- قاعدة بيانات Supabase كاملة للمنتجات والعملاء والطلبات والاهتمامات والعروض والمصروفات.
- سجل حالات الطلب.
- محاسبة: الإيراد، تكلفة المنتج، الشحن، رسوم الدفع، المصروفات، وصافي الربح.
- تتبع اهتمام العميل: مشاهدة، بحث، مفضلة، سلة، بدء الدفع، شراء.
- الدفع مقدمًا مفعّل في تصميم البيانات، والدفع عند الوصول غير مفعّل.
- طبقة جاهزة لبوابة دفع مستقبلية.
- Edge Functions مبدئية لاستيراد المنتجات وإرسال إشعارات الطلبات.
- وضع Demo يعمل بدون قاعدة بيانات حتى تتمكن من فتح المشروع من الهاتف ومشاهدة الواجهة.
- صور المنتجات تُحفظ كروابط في قاعدة البيانات بدل رفع ملفات الصور يدويًا.
- مجلد `design-reference` يحتوي الصور المرجعية التي أرسلتها، لاستخدامها أثناء ضبط التفاصيل البصرية.

## ملاحظة مهمة عن AliExpress / Amazon / Alibaba / Noon

المشروع يحتوي **واجهة وعقد استيراد** بالرابط، لكن لا يجوز اعتبار الكشط المباشر من هذه المنصات مضمونًا؛ بعض المواقع تمنع أو تقيد الوصول الآلي، وقد تتطلب API أو مزود بيانات معتمد. لذلك يوجد Adapter منفصل لكل مصدر يمكن ربطه لاحقًا دون إعادة بناء المتجر. لا يتم تجاوز أنظمة الحماية أو شروط الاستخدام.

## تشغيل سريع من الهاتف

### 1) قاعدة البيانات
افتح Supabase من المتصفح على الهاتف، أنشئ مشروعًا جديدًا، ثم افتح SQL Editor وانسخ محتوى:

`supabase/schema.sql`

### 2) إعداد الموقع
انسخ:

`config/config.example.js`

إلى:

`config/config.js`

ثم ضع `SUPABASE_URL` و`SUPABASE_ANON_KEY`.

**لا تضع service-role key في الموقع.**

### 3) النشر
يمكن رفع المجلد إلى GitHub من الهاتف أو نشره عبر أي استضافة Static تدعم الملفات. إذا استخدمت GitHub Pages، استخدم الـworkflow الموجود في:

`.github-workflow-static.yml`

### 4) لوحة الإدارة
افتح:

`/admin.html`

على الهاتف.

## منطق الإدارة والموقع

لوحة الإدارة **لا تعيد كتابة ملفات HTML عند تغيير المنتج**. بدل ذلك:

`Admin → Supabase Database → Website`

وبالتالي تعديل السعر أو الصورة أو المخزون أو العرض في الإدارة يظهر في المتجر من المصدر نفسه.

## محاسبة الطلب

المعادلة الأساسية في النظام:

`صافي الربح = إجمالي المدفوعات − تكلفة المنتجات − الشحن − رسوم الدفع − المصروفات الأخرى`

ويتم الاحتفاظ بتكلفة المنتج داخل بند الطلب حتى لا تتغير أرباح الطلبات القديمة إذا تغير سعر المورد لاحقًا.

## الأمان

- Supabase RLS مفعّل في المخطط.
- مفاتيح الخدمة لا توضع في Frontend.
- عمليات الإدارة الحساسة يجب تنفيذها من Authenticated Edge Functions.
- يفضل إنشاء حساب Admin مستقل قبل تشغيل المتجر الحقيقي.
- لا تستخدم بيانات العملاء التجريبية في الإنتاج.

## ما بقي قبل الإطلاق التجاري

1. إنشاء مشروع Supabase وربطه.
2. إنشاء مستخدم Admin وتقييد سياسات الإدارة.
3. ربط مزود البريد transactional email.
4. اختيار مزود دفع وإضافة webhook.
5. ربط Adapters مسموحة لمصادر المنتجات أو APIs رسمية/مزود بيانات.
6. إدخال سياسات الشحن والاسترجاع والخصوصية الخاصة بالنشاط التجاري.
7. اختبار الطلب والدفع والمخزون على بيئة تجريبية قبل البيع الحقيقي.
